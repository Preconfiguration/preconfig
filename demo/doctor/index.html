      How Doctor decides
      
      
      
        
      
          
      Rules, and no guessing
      
          
        
            
      • Doctor reads the log's step markers to find the step that failed, then tries its rules on that step's lines, the most specific first: a blocked download before a missing package, a missing package before a failed test.
        • 
            
      • Each rule was written for a real kind of failure. When none fits, Doctor says it doesn't know and shows the lines that look like errors. It never changes the spec on a guess.
        • 
            
      • Only causes that live in the spec come with a change. A blocked network, a stale lockfile, an unset secret or a test that fails on the code get an explanation and where to fix it instead.
        • 
          
      
        
      
        
      
          
      What is real here
      
          
        
            
      • Every recorded log above is what the machine printed during a real run of preconfig verify, or a real Docker build, on the test machine on . Eight of the nine failures were made on purpose, and the ninth comes from the test machine's network; each has a known cause.
        • 
            
      • The diagnosis and the rebuilt files come from the engine's own Go code, compiled to WebAssembly for this page. A test compares every answer with the command line's.
        • 
            
      • Where a fix says it was proven, the changed spec was run again on a clean machine, and the result shown is that run's.
